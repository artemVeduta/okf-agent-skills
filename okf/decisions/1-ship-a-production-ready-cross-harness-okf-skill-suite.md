# Ship a production-ready cross-harness OKF skill suite

Status: Closed.

## Destination

Publish `v0.1.0` of a public, deterministic-tested, cross-harness OKF skill suite that supports bounded suite-owned writes and incremental bounded synchronization. Broad, destructive, identity-changing, recovery-dependent, and cross-repository writes are explicitly deferred.

## Notes

- This map explicitly carries execution through the first usable release; it does not stop at a specification.
- Use the Wayfinder, research, domain-modeling, codebase-design, skill-creator, `writing-great-skills`, `prototype`, test-driven-development, and verification-before-completion skills when their phase is active.
- Treat Matt Pocock's `writing-great-skills` skill as a required authoring reference and pin the reproducible upstream source at [commit `ed37663`](https://github.com/mattpocock/skills/blob/ed37663cc5fbef691ddfecd080dff42f7e7e350d/skills/productivity/writing-great-skills/SKILL.md).
- Treat ["Building Great Agent Skills: The Missing Manual"](https://www.youtube.com/watch?v=UNzCG3lw6O0) as complementary authoring evidence from the same source, not independent corroboration; preserve transcript provenance and adopt its project-specific consequences through the map's dedicated tickets.
- Code is authoritative for executable behavior. In code-backed projects, OKF stores compact durable context that cannot be recovered adequately from code; it must not mirror configs, constants, or implementation. In knowledge-only projects, the OKF bundle may be the complete source of truth.
- Automatic lifecycle behavior may read and execute only bounded suite-owned notice writes that pass admission, project mode, ownership, evidence, scope, semantic-preservation, and post-write validation. The manual-operation guard, ledger, lock, approval flow, and recovery flow are not shipped in `v0.1.0`; broad operations are deferred.
- Use a separate OKF subagent or equivalent isolated workflow when supported, especially during code review.

- Approval baseline: superseded by the concrete matrix in [Design operational trust tier matrix for skill operations](https://github.com/artemVeduta/okf-agent-skills/issues/11), which is closed. The budget-specific retrieval tension and contract are removed by [Replace budget-aware retrieval with index navigation](https://github.com/artemVeduta/okf-agent-skills/issues/36). Native find/read uses the separate orientation, scope, and disclosure rules recorded there.
- Research evidence, inferences, candidate defaults, and product decisions are distinct. Numeric lifecycle thresholds remain configurable candidates until fixture benchmarks justify defaults.
- `v0.1.0` requires deterministic and fixture-based contract tests. Live process tests across all three harnesses are deferred to `v0.2.0`.
- Target macOS and Linux in v1; Windows and Obsidian application integration are out of scope.
- Never introduce Husky into a target project. Integrate only when it already exists; add GitHub validation only when a GitHub project is detected.
- Repository setup must reach public-project quality: MIT license, full README, contribution/security governance, protected-main workflow, CI, releases, `AGENTS.md`, and `CLAUDE.md`.

- [Audit the OKF spec research note for normative drift](https://github.com/artemVeduta/okf-agent-skills/issues/34) — Normative drift in `02-okf-v02-spec.md` was systemic, not a one-off: 29 findings, 12 caused by tabulating prose whose normative marking is ragged. Root cause was a binary NORMATIVE/editorial taxonomy with no slot for `SHOULD` and no slot for spec silence, so silence got backfilled with a guess and a table cell made the guess look quoted. Worst case put a producer `MUST` in a consumer-validation table, which would have built a validator that rejects conformant bundles. Five conventions now prevent recurrence, the load-bearing one being that a status cell with no RFC 2119 keyword stays empty. 23 sections verified clean; other `docs/research/` notes are unaudited and may share the pattern.

The three questions this map asks are answered and built:

- **Storage** — an OKF bundle in the repository, with the bundle-root `index.md` doubling as the write gate. Reads may federate through `okf-workspace://`; writes stay in the current repository.
- **Maintenance** — bounded notice writes through `okf-write`, narrow automatic maintenance through `okf-lifecycle`. Broad operations are out of scope for this release and the skills refuse them.
- **Injection** — orientation pushed at a session seam, gated on the `.okf-active` marker; content pulled by native navigation along a fixed path. Retrieval machinery was deleted outright in #36 and none of it came back.

The five skills now exist behind the `okf` router. Before this branch `skills/` was absent and the inventory test was passing vacuously, so the green suite was evidence of nothing on the one thing the project is named for.

Remaining gaps, all on #10: `main` is unprotected and does not yet carry the code, no `v0.1.0` tag exists so the documented install command does not resolve, and the release has not been dogfooded in a real harness.

Two release-positioning items stay open by decision, not by omission: the support ceiling ships labelled provisional with no calibrated claim, and coexistence with `fabricioctelles/okf-open-knowledge-format` is settled by explicit deferral — the README claims no compatibility, replacement or interoperability in either direction.

#15 (live cross-harness acceptance testing) remains deferred to `v0.2.0`.
