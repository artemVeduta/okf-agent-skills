2. 12-Phase Pipeline

Click a phase to see details.

Phase 1 — Cost Model Admission

Checks that a calibrated cost profile exists for this deployment. If no tokenizer or profile is available, returns insufficient immediately — there is no universal character divisor.

Phase 2 — Allowance & Provenance

Resolves the allowance from three sources:

explicit → use declared allowance (normal path)
estimated → use declared allowance, mark degraded
unknown + fallback → use fallback, mark degraded
unknown + no fallback → insufficient

Phase 3 — Reserve Carving

Task KindFractionMinimum
exploration20%200
research25%240
review30%300
feature35%360
audit35%360
migration40%420
debugging45%500

Reserve is carved before any selection. A declared output requirement may increase the reserve but never reduces the profile minimum.

spendable = allowance − reserve

Phase 4 — Honest Retrieval Floor

The smallest truthful output: receipt + notice + one entry per exact demand. Below this floor, even a refusal cannot be emitted truthfully → insufficient.

The floor grows with the number of demands — "never silently drop a demand" makes the smallest truthful envelope a function of the request, not a constant.

Phase 5 — Discovery

Escalating channel purchases: inventory → index → frontmatter → body

Under satisficing, stops when the evidence rule is satisfied. Under exhaustive, examines every channel in every scope.

On the in-context seam, discovery output is charged to the context ledger. On the out-of-context seam, it stays on the work ledger only.

Phase 6 — Exact Demands

Resolved before ranking. Matches by id, path, or source reference. Unresolved references produce UNRESOLVED entries.

A demand that cannot fit even at its cheapest tier (LINE) triggers an explicit insufficient refusal with a quantified shortfall.

Phase 7 — Evidence-Bound Filters

Predicates evaluated only when the concept has been observed at the CARD tier. A predicate cannot be evaluated on unread data.

Precedence rule: FILTERED (budget-independent exclusion) dominates CLIPPED (budget-dependent) — reporting a policy-rejected concept as CLIPPED would suggest "raise the allowance", which can never surface it.

Phase 8 — Ranking

Score computed from clause matches against progressively revealed text:

Match LocationWeight
id, path2×
title4×
description3×
tags3×
type1×
section text3×

strong (≥6) → asks FULL. medium (≥3) → asks SECTION or CARD. weak (<3) → asks LINE.

Phase 9 — Tier Allocation

Four-tier ladder: LINE → CARD → SECTION → FULL

9a. Demands first: each demand gets the highest tier that fits, degrading down the ladder. Never silently dropped.

9b. Ranked fill: remaining concepts allocated by score, each at its asked tier, degrading when necessary.

Allocation is atomic — each concept gets exactly one tier. No fragment tiers.

Phase 10 — Bounded Omission Structure

Named counts:
CLIPPED — matched but no tier fit
FILTERED — policy-rejected
MISS — all channels examined, nothing matched
UNDISCOVERED — work or context ran out before examination
UNSEARCHED — evidence rule satisfied before examination
UNRESOLVED — exact demand had no match
Departure fields:
unevaluatedPredicates — "n candidates ranked without their status read"
bypassWarnings — when an exact demand passed a filter it should have failed

Form collapses to counted when names exceed nameCap or noticeShareCap.

Phase 11 — Receipt

12+ field audit record. Per-line context spend with bound/charged/observed triples. The receipt is a context-ledger item that must be reserved for — it was the largest source of silent overruns before the fix.

Receipt size depends on the selection it reports, so it uses the same largest-reachable reservation rule as the omission notice.

Phase 12 — Audit

verified — deployment is audit-capable, bounds held. unverified — deployment is audit-blind, no post-emission measurement exists.

A falsified bound triggers invalid: content is discarded, the profile is quarantined, but the invalid envelope itself must be bounded by a fixed content-free literal — it cannot be bounded by the profile it just quarantined.

6. Verdict Classes

SELECTED
Scored, fit, admitted
nextAction: nothing
DEMANDED
Exact demand, honored at best available tier
nextAction: raise allowance for FULL
CLIPPED
Context allowance ended; no tier fit
nextAction: raise allowance or name as exact demand
FILTERED
Policy rejection (deprecated/draft)
nextAction: turn off that filter
MISS
All channels examined, nothing matched
nextAction: change the query
UNDISCOVERED
Work envelope or context budget ended
nextAction: depends on ledger (work vs context)
UNSEARCHED
Evidence rule satisfied before examination
nextAction: switch breadth to exhaustive
UNRESOLVED
Exact demand had no match in corpus
nextAction: check the reference

Precedence Rules

FILTERED dominates CLIPPED — budget-independent exclusions win. Reporting a deprecated concept as CLIPPED would attach "raise the allowance", which can never surface it.
Demands bypass ranked filters — with an explicit bypass warning in the omission structure.
MISS requires body observation — a zero-score concept read only through an index is UNSEARCHED evidence wearing a MISS label. The verdict is gated on full body observation.

7. Key Design Resolutions

QuestionResolution
How is the budget obtained? Provenance declaration: explicit (harness attests), estimated (degraded), unknown (insufficient unless fallback exists)
Default retrieval breadth? Task-kinded: audits/migrations/reviews are exhaustive; everything else satisficing
Progressive disclosure? Four-tier ladder: LINE → CARD → SECTION → FULL. Atomic (concept+tier) allocation
SECTION honesty? SECTION = CARD + complete section manifest + selected sections. Without manifest, truncated looks like full
Which retrieval modes? Boolean AND (clause coverage). No stemming, no synonyms, no stopword deletion, no substring matching
importance field? No. Informativeness is document-frequency-derived, corpus-local, purely lexical
Standalone skill or shared runtime? Shared pure function invoked by all skills. Harness-specific adapter attests seam, provenance, audit capability
Receipt reservation? Must be reserved for. Size depends on selection it reports — same largest-reachable rule as the notice
Invoice envelope bounded? Bounded by a fixed content-free literal measured once per deployment — not by the quarantined profile
Query normalization? NFC case folding, identifier subterms added, original preserved. No stopword deletion, no minimum length, no substring stems

8. Fixture Reality & Provenance Guarantees

What the Prototype Tests

Internal consistency of the decision procedure
Order-correctness of the 12 phases
No self-pricing oracles (the #28 defect class)
No silent overruns (136,080 continuous allowance sweep)
Monotonicity in allowance (#28 spxt- regression)
Atomic tier allocation (no fragment tiers)
No duplicate verdicts for any concept
Every exit path emits a complete receipt shape
Every non-selected verdict carries a causally sufficient nextAction

What It Does NOT Prove

Absolute cost profile accuracy — no real tokenizer
Real OKF document calibration — fixture is hand-crafted
Real serialization overhead — no notice renderer
Filesystem enumeration — no symlinks, permissions
Cache behavior — pure function, no cross-call state
Clock-based timeouts — no clock in the fixture
